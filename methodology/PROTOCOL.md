## 1. 独立单位与样本量
- 独立单位是**概念簇**：同一概念的改写、翻译、难度递增版放进同一簇。簇不能跨 dev/val/密封测试；重复次数不算样本。
- **试点**：30 个独立开发簇，每个条件 2 次，用来估计簇级配对差的标准差 σ_d 并检验评分器。
- **正式密封测试**：按功效规划，`N≈ceil(((1.96+0.84)σ_d/δ)²)`。80 簇、R=2 只是参考起点（σ_d=0.15、δ=0.05 时 N=71）。要证明“至少提升 δ”或非劣时，按到边界的距离重算。规划在看正式结果前冻结；达不到规划规模的只报描述结果或“不确定”。
- R 按成本决定是否增加，不用“方差占比 25%”这个开关。

## 2. 主指标与失败
- 主指标 = **全部计划运行的均值**：题内 → 簇内 → 簇间按冻结权重平均。截尾均值只作敏感性分析。
- 运行错误、解析失败、有效零分、拒答、严重错误分别计数。被测系统失败按 0 计入。基础设施错误允许预先规定的同配置补跑 1 次，占用同一个槽位，两次都留记录。评分未知标 `unscored`，按 0 报保守均值，并禁止据此升级版本。条件成功均值只作副指标。

## 3. 检验与判定
- **簇配对 bootstrap**：同一个簇索引同时携带 A/B、所有模型和全部簇内记录。最终 10,000 次、开发 2,000 次，固定种子，用 95% 分位数区间。
- 确认性假设族（各目标模型收益、关键非劣、交互）用 **Holm** 处理有效 p 值。没有 p 值时，预先选定用 Bonferroni 同时区间。BH 只用于探索。不得把 bootstrap 样本落在零两侧的比例当作 p 值。
- 判定看校正后的下界 L：L>0 为统计改善；L>δ 为至少达到 δ 的改善；L>−m 为非劣。δ 和 m 由案例预先冻结。另外还要过严重错误、正确性、成本硬门槛。
- 固定 N，不因区间已显著就提前停止。故障或泄露可以停，但不能据此宣布成功。第一版不做序贯检验（Lan–DeMets）。
- **默认规则（不是禁令）**：消融前基线通过率宜在 20%–80%。超出范围时，先调整题目难度或验收条件；确实要跑的，在预注册计划里写明理由（教训见 [retros/2026-10-13-benefit-49.md](../retros/2026-10-13-benefit-49.md)）。

## 4. 裁判校准
1. 能用程序验证的事实、格式先交给独立检查器。绝对分 Q 和 A/B 偏好分别校准。
2. 规则开发集：约 30 对。**首次完整校准：冻结检查集约 200 对、至少 50 簇**（工程预算，不是通过门槛），不参与调规则。
3. 两人独立盲标全部检查对，分歧由专家裁决，原始标签和理由都保留。
4. 报告人机和人人一致率、κ、混淆矩阵、严重错误漏检率、簇级区间。不能用单一指标放行。
5. 要宣称“相对人工非劣”，需要另建独立参考金标；否则只报一致性。
6. 双顺序（冲突交人工）、等义长短控制、来源盲化、自偏好审计。
7. **按目标模型复核**：首次完整校准之后，每换一个被测模型，只抽约 50 对该模型的输出做双人复核。一致性相比完整校准明显下降（预注册下降幅度）时，才对该模型重做完整校准。裁判模型、评分表、解析器或任务分布变化，仍需重做完整校准；检查失败后修了裁判，必须用新的检查集确认。
- 裁判和被测模型不用 openrouter-* 模型。

## 5. 跨模型反转与 tokenizer
- 同一批簇上跑每个模型的 A/B，计算 Δ_m 和 I=Δ_m1−Δ_m2，重采样共用簇索引。交互显著只说明收益不同；**确认反转**还需要两个方向各自有区间支持。交互的功效单独规划。
- 每次运行记录：模型快照、服务商、系统/消息提示哈希、**tokenizer 名称/版本**、**聊天模板哈希**、工具定义、运行器版本、环境、采样参数、输入/输出/推理 token（CLI 的累计值要做差）、截断、停止原因、缓存状态。闭源看不到的字段填 null，不从 token 总数去猜。
- tokenizer 是机制假设，没有专门设计的实验之前不作因果归因。

## 6. 串行与运行隔离
- 每次运行用干净会话和干净工具状态。同簇内 A/B 随机交错；缓存命中不算独立重复。
- **隔离预检（硬性要求）**：禁用用户技能目录和项目文档的自动加载，并用日志验证；污染的单元记为环境失败（教训见 [retros/2026-10-14-luna-max-eval.md](../retros/2026-10-14-luna-max-eval.md)）。
- 共享资源（同一账号、同一工作目录、限流）的任务串行执行或使用独立副本；并发数和超时写进计划。
- 密封集访问账本：版本、访问者、时间、候选哈希、用途。看汇总分数也算一次使用。
- 重活走 Mac mini Codex。box 和 Mac mini 的结果分环境报告，不混成一次 A/B。

## 8. 案例接入模板
案例只补“评测集 + 打分标准 + 案例配置”；运行、统计、日志和汇总由框架统一负责（报告 §4）。

| 部分 | 案例提供 | 框架验收 |
|---|---|---|
| 任务卡 | task_id、cluster_id、split、输入引用、领域/难度/语言、来源与许可 | 查重、簇隔离、干净环境能加载 |
| 评分 | `score(task, output, trace) → {score, dimensions, critical_errors, status, evidence_refs, scorer_version}`；正例、负例、边界例 | 改动后所有条件重判 |
| 裁判 | 模型/提示/评分表/解析器哈希、校准报告 | 按 §4 执行，每个目标模型分别确认 |
| 计划 | 用 §7 模板 | 未填的门槛只能做描述性报告 |
| 隐私 | 内容能否离机、逐簇统计能否离机、授权的模型端点 | 本地模式不调用未授权的外部端点 |
| 汇总 | 版本、计划/实际 N 与 R、A/B 均值、Δ、区间（是否校正）、各类失败计数、token 与成本、逐模型结论、交互、密封集访问 | 失败与缺失守恒，报告可重算 |

**只回报汇总的两种模式**：
- **A. 内容不离机，逐簇统计可离机**：上报实验内稳定的匿名簇 ID、层与权重、各模型 A/B 的簇均值和差值、计划/完成/失败计数、token 汇总、版本摘要。中心能重算均值、簇 bootstrap 和差中差，但不能验证文本评分是否正确。HMAC ID 只是假名化，不是匿名化。
- **B. 逐簇统计也不离机**：本地用冻结代码算出均值、CI、校正结果，只上传全局结果和计数。报告必须注明“本地计算，中心未独立重算”。哈希不能证明真的执行了对应的代码或数据。
- 若“不出本地”也包括模型服务，生成和裁判都必须在本地或授权边界内运行；本地跑工具、再调用云端 API，仍然会把内容发出去。

## §10 防记忆作弊（硬性要求，适用于所有执行器）

1. 每次运行使用全新的空记忆和独立配置目录，关闭跨会话记忆和项目规则。
2. 运行前确认记忆为空；运行后检查是否有新写入的内容，有写入则该次运行作废，计入失败清单并注明原因。
3. 每套评测加入若干换了说法的探针题，用来检测执行器是否记住了以前的答案；探针题结果单独报告，不计入主指标。
