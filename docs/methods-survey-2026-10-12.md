## 结论先行（5 条）
1. **题少时，最大的噪声来自“题”，不是“次”**。每格跑 5 次只能压低单题内部的抖动。2–3 题的角色均分本身没有统计意义。现在最该做的是**扩题**（每角色 ≥8–10 题，可以用程序批量造变体），并且**比较时用配对差值**（同题、同次数下 A−B）。Anthropic 的“给评测加误差条”系列建议正是：报告标准误、按题聚类、减少题内方差、分析配对差、做功效分析。【已核】
2. **“去最高最低取平均”应改成“报全部次数 + 均值 ± 标准误 + pass^k”**。截尾平均会丢掉恰好最关键的信息：偶发的 0 分（例如公开侧模型 B 那次输出无法解析）。对 agent 来说，“偶尔崩一次”就是可靠性问题。τ-bench 专门提出了 pass^k（k 次全部成功的概率）来度量这一点。【已核】
3. **防过拟合要做到“三分离”**：
   - 规则来源与判分口径分开写，由不同的人或文档负责；
   - 判官与作答者用不同的模型族；
   - 保留集只在“定版”时跑一次，并记账。

   LLM 判官有已证实的自偏好、位置偏差、啰嗦偏差（MT-Bench 论文；Panickssery 等）。【已核】
4. **全满分说明题没有区分度，要优先修**。学 SWE-bench Verified：先人工审题（题意清楚、检查正确、可解），再按难度分层；补“诱导题”“矛盾证据题”和多步题，直到强模型也会失分。满分题保留为回归题，但不计入对比。
5. **prompt 优化的数据纪律照抄 DSPy/GEPA**：DSPy 建议多数 prompt 优化器按 20% 训练 / 80% 验证切分，因为 prompt 优化器容易在小训练集上过拟合；另留测试集。GEPA 反过来，尽量加大训练集，验证集只要足够代表下游分布即可。我们题少，所以**验证集的稳定性 > 训练集大小**。【已核】

## 一、小样本统计（概念入门 + 借鉴）

### 1.1 方差从哪里来
- **是什么**：评测分数的波动有两层。①题与题之间难度不同（题间方差）；②同一题多跑几次，模型输出随机（题内方差）。Anthropic 的文章把评测题看作从一个看不见的“题目总体”中抽出来的样本，用中心极限定理算均值的标准误（SEM），95% 置信区间 ≈ 均值 ± 1.96×SEM。【已核】 https://www.anthropic.com/research/statistical-approach-to-model-evals ，论文 https://arxiv.org/abs/2411.00640
- **借鉴**：每角色 2–3 题时，题间 SEM 估都估不准。多跑次数只能减小②，减不了①。所以：
  - (a) 结论只按“题级”说，例如“调度①从 0.2 提到 0.4”，不说“调度角色提升”；
  - (b) 扩题是第一优先。

### 1.2 聚类标准误
- **是什么**：如果几道题本质是同一个题源的变体（例如同一篇阅读材料的多个问题），它们不独立。Anthropic 原文说，聚类后的标准误可以比朴素标准误**大三倍以上**；忽略聚类可能“检测到”根本不存在的差异。【已核】Inspect 的 Scoring Metrics 文档也内置了 clustered standard errors。【已核：文档目录写有“clustered standard errors, … reducing epochs”】 https://inspect.aisi.org.uk/scoring.html
- **借鉴**：将来用程序批量造变体扩题时，同一母题的变体要**按母题聚类**算误差，不能当成独立的题。

### 1.3 配对比较
- **是什么**：比较 A、B 两种 prompt 时，在**同一批题**上算每题的差值 dᵢ = Aᵢ − Bᵢ，再对差值求均值和标准误。题目难度的影响相互抵消，同样题数下能检测到更小的差异。Anthropic 第 4 条建议：报告均值差、标准误、置信区间和相关性。【已核】
- **借鉴**：编译器的门槛“两边都不掉分”，改为“配对差的 95% 区间下界 ≥ −δ”。δ 是事先定的容忍度，例如 0.05。这才是“不掉分”的统计说法，也就是非劣效检验。

### 1.4 Bootstrap（自助法）
- **是什么**：把数据有放回地重抽很多次，每次重算统计量，用分布的分位数作为置信区间。不依赖正态假设，适合小样本和 0/1 分数。（统计学常识，本次没有单独核对原文出处。）
- **借鉴**：做**两层 bootstrap**：先重抽题（按母题），再在题内重抽次数。题少时区间会很宽，这本身就是有用的信息：告诉你“还不能下结论”。

### 1.5 功效分析：要跑多少
- **是什么**：事先算出“想检测到 Δ 的差异，需要多少题、每题多少次”。Anthropic 第 5 条：功效公式能告诉你每题该重抽几次、能抽多少题；题太少的评测可能“不值得跑”。【已核】
- **借鉴**：先用已有数据估题内方差，再算“检测 0.1 的差异需要几题 × 几次”。很可能结论是：5 次足够或偏多，题不够。可以把预算从“次”挪到“题”。

### 1.6 pass@k 与 pass^k
- **pass@k**：k 次尝试里**至少一次**成功的概率，出自 Codex/HumanEval 论文。论文摘要：每题采样 100 次，可以解出 70.2% 的题，而单次只有 28.8%。【已核】 https://arxiv.org/abs/2107.03374 。论文给出的无偏估计式 1 − C(n−c,k)/C(n,k)（n 次中 c 次成功）出自正文，本次没打开正文，【未核实】。
- **pass^k**：k 次**全部**成功的概率，由 τ-bench 提出，用来衡量 agent 的可靠性。摘要原话：gpt-4o 这类 SOTA agent 在 <50% 的任务上成功，并且很不稳定，零售域 pass^8 < 25%。【已核】 https://arxiv.org/abs/2406.12045
- **借鉴**：我们的角色是“调度/执行要每次都对”，所以主指标应该看 **pass^k**（例如 k=5 时全部通过的比例）和均分，而不是 pass@k。截尾平均恰好把 pass^k 关心的失败抹掉了。

## 二、数据切分与防过拟合

### 2.1 调优 / 验证 / 保留
- **是什么**：调优集用来改 prompt；验证集用来挑版本；保留集（测试集）只在最终定版时看一次。每多看一次保留集，它就多“泄露”一点。DSPy 文档建议：训练集（含其子集验证集）30 例就常有价值，目标至少 300 例；另外留一个 held-out 测试集。【已核】 https://dspy.ai/learn/evaluation/data
- **借鉴**：
  - (a) 保留集的使用次数**记账**（像量化研究的实验账本 N），每看一次加 1；
  - (b) 题少时可以用**留一角色/留一母题交叉验证**代替固定切分；
  - (c) 编译器的“泛化验证”（非原项目任务）本质就是一个外部保留集，要一直保持“没见过”。

### 2.2 污染检测
- **是什么**：题目被模型训练数据吃进去，分数就虚高。BIG-bench 在所有任务文件里放一个“canary”字符串，目的是防止任务泄露进网页抓取的训练数据。【已核】 https://github.com/google/BIG-bench
- **借鉴**：私有题本来就在原机器上，污染风险低。真正的风险是**“口径泄露”**：编译器的规则和判分来自同一份文档，等于把答案写进了题面。对策：
  - (a) 判分清单由与规则作者不同的人写，或用历史真实验收记录反推；
  - (b) 在私有题文件里加 canary，防止它们被误放进规则提炼的语料；
  - (c) 定期做“改写扰动”（换措辞、不换要求），看分数是否稳定。参见 Sclar 等关于格式敏感性的研究（现有材料已引用，本次未重新核对）。

## 三、LLM-as-judge 的偏差与校准
- **是什么**：MT-Bench/Chatbot Arena 论文系统研究了 LLM 判官的**位置偏差、啰嗦偏差、自我增强偏差**以及推理能力有限的问题，同时发现 GPT-4 类判官与人类偏好的一致率超过 80%，与人与人之间的一致率相当。【已核】 https://arxiv.org/abs/2306.05685 。Panickssery 等发现：LLM 能识别自己的输出，自识别能力与自偏好强度呈线性相关。【已核】 https://arxiv.org/abs/2404.13076
- **借鉴**：
  1. **判官和作答者不同族**。同族时，现行“记 SKIP”的规矩是对的，要坚持。
  2. 两两比较时**交换 A/B 顺序各判一次**，两次结论不一致就记平局。
  3. **评分细则写成可勾选的二元项**（“是否有‘需要你决定’一行”），不用 1–10 分；能转成程序检查的都转。
  4. **校准**：抽 10–20 份输出让人判，算判官与人的一致率；一致率低的项不用判官。
  5. 判官 prompt 不能复用编译器规则的原文，否则就是第二个同源风险。

## 五、prompt 优化的评测规矩（DSPy / GEPA）
- **DSPy**：多数 prompt 优化器建议 **20% 训练 / 80% 验证**，原因是“prompt-based optimizers often overfit to small training sets”；GEPA 例外，它最大化训练集，验证集只需足够代表下游分布。【已核】 https://dspy.ai/learn/evaluation/data
- **GEPA**：采样轨迹，用自然语言反思诊断问题，提出并测试 prompt 改动，再从自身尝试的 Pareto 前沿合并互补的经验。摘要数字：6 个任务上平均比 GRPO 高 6%、最多高 20%，rollout 最多少 35 倍；比 MIPROv2 高 10% 以上（AIME-2025 +12%）。【已核】 https://arxiv.org/abs/2507.19457 。DSPy 的 GEPA 文档写明 `compile(student, trainset=…, valset=…)`，valset 用来做 Pareto 选择。【已核】
- **借鉴**：
  1. 编译器迭代时：失败检查项 → 改写器 → 候选规则集。候选只在**验证集**上比，Pareto 选择也只看验证集，保留集不参与。
  2. 迭代轮数和候选数都计入“试验次数”。最后在保留集上报结果时，要说明一共试了多少候选（多重比较）。
  3. 题少的情况下，**验证集宁可大、训练集小**（DSPy 的 20/80 思路）。反思用的失败样本可以来自用户真实纠正，不一定要来自评测题。

## 六、成本与效果权衡
- 每次调用约 2.3 万 token 的固定开销是主要成本（材料里的实测）。可以这样做：
  1. **预算从“次”挪到“题”**：按 1.5 节的功效分析，可能每格 3 次就够，省下的预算用来扩题。
  2. **分层评测**：先每格 1 次粗筛候选，只对进入前列的候选加到 5 次。
  3. **压缩固定上下文**：现有材料已建议。
  4. **缓存**：两份材料里有六成以上输入命中缓存，固定前缀放最前面，保证缓存命中。
  5. 看板加“每 0.1 分提升的 token 成本”一列，让效果和成本同屏。
