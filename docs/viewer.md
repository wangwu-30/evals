## Use and scoring

Use the home-page “看原文” link, an evaluation's primary button or score cell, or a batch row's “原文” link. Choose one model, a question, and up to three conditions. The first condition is the control; other columns compare only with it. Question order defaults to the largest average length difference and can return to original order. Question and condition lists support filtering. Historical batch links keep that batch and repetition selected.

The primary score is the average of all eligible runs. Model timeouts, missing answers, empty answers and truncations count as zero and are also listed separately. Infrastructure failures are excluded from every average. A model/condition/batch cell with more than 10% infrastructure failures is marked “数据不全”. The average after removing one highest and one lowest score is a small reference only.

Length counts Chinese characters plus English words or number strings. Only runs with stored, nonempty output and no infrastructure failure contribute to the length average. Truncated text still contributes. The default displayed run is closest to that average, with earlier repetitions breaking ties. Missing stored text is distinguished from a recorded empty answer. Old failure clues are labeled “旧记录没写失败类型，按模型失败算”. Real-data regression tests reproduce Sonnet full = 0.60 and removal of section 4 = 0.30.

PR #1's historical report is not edited. Its headline trimmed-mean convention is superseded by the all-runs mean required for the site; its evaluation is not included in this branch.

## Data contract and publication boundary

The build creates `site/c/<eval>.html`, an index, and model/question/condition JSON. Large selections contain run metadata plus lazy per-run text files; there is no framework or model API. URL state includes `m,q,c,r,bad,order,p,k`; `b` selects a historical batch, `v` the phone mode and `a` the phone comparison condition. The measured worst three-condition first load, including the uncompressed shell, all shared assets, index, selection metadata and largest selected run payloads, is recorded in the implementation report.

Existing files under `data/` remain unchanged. New `viewer.json` files overlay `check_labels` and the empty optional `model_labels` hook when loading existing evaluations. New MiniMax evaluations store those maps directly in `eval.json`. Check labels for daily-skill are drafts requiring owner review; no labels for excluded PR #1 were added.

The build backfills by exact model + condition + repetition + latency, accepting only unambiguous matches. It must match all 165 box-rescored records or fail. The final Mac batch matches 103/110; seven stay without text. Backfilled records carry `text_source`. Ingest preserves outputs, writes `fail_type` and `text_source`, respects explicit runner failure types, and rejects the retired `--strip-output` option.

Every candidate record, including reasons, evidence, thinking, added text and associated prompt, is scanned before aggregate or raw publication. Matches remove the whole record. Logs contain counts and categories only. Filters exclude holdout items and teamrecall private labels, including nested labels. Company-side and hpo evaluations get conclusions only. The build no longer copies `data/` wholesale: only accepted normalized records are downloadable. Source artifacts, private receipts and split inventories are not published. Every HTML page has noindex; robots.txt disallows crawling.
